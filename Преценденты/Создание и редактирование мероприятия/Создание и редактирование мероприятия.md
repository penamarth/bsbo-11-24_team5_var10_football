Рамки. Приложение организации мероприятий и продажи билетов.

Уровень. Задача, определенная пользователем.

Основной исполнитель. Менеджер.

Заинтересованные лица и их требования.

- Менеджер. Хочет быстро создавать и настраивать мероприятия и матчи, управлять готовыми картами стадиона, изменять доступность мест и сохранять изменения без ошибок.
- Посетитель. Хочет получать актуальную информацию о доступных местах и приобретать билеты только на свободные места.
- Организатор мероприятия. Хочет получать актуальную схему размещения зрителей и информацию о занятых и свободных местах.
- Компания владелец стадиона. Заинтересована в сохранности данных, устойчивости FTS к сбоям и своевременном обновлении информации о мероприятиях.

Предусловия. Менеджер идентифицирован и аутентифицирован в FTS. В EventRepository доступны мероприятия и карты стадиона.

Результаты (Постусловия).

- Новое мероприятие создано или существующее мероприятие обновлено.
- Карта стадиона создана и сохранена в EventRepository либо выбрана из уже существующих.
- Матч создан и связан с выбранной готовой картой стадиона.
- Изменения доступности мест сохранены.
- Данные мероприятия, матча и карты записаны в хранилище.
- Пользователь получил подтверждение успешного сохранения.

Основной успешный сценарий (или основной процесс)

1. Менеджер инициирует управление мероприятиями, запуская FTS.
2. FTS загружает данные мероприятий из EventRepository.
3. Менеджер открывает панель управления картами стадиона и создаёт новую карту либо просматривает уже существующие карты.
4. FTS создаёт экземпляр карты стадиона, заполняет его местами и сохраняет карту.
5. Менеджер выбирает опцию создания нового мероприятия, создавая новый объект класса мероприятия.
6. FTS сохраняет мероприятия.
7. Менеджер выбирает опцию создания матча и указывает мероприятие, название, коэффициент цены и время проведения.
8. FTS предлагает выбрать готовую карту стадиона: уже существующую в EventRepository или только что созданную в панели карт.
9. FTS копирует выбранную карту  и привязывает копию к создаваемому матчу.
10. FTS создаёт матч и сохраняет его.
11. Менеджер изменяет параметры необходимых мест с помощью интерфейса.
12. FTS сохраняет внесенные изменения.
13. Менеджер завершает настройку и отправляет команду сохранения.
14. FTS сохраняет изменения мероприятия и матча.
15. FTS отправляет подтверждение успешного создания мероприятия.
16. Менеджер получает уведомление об успешном завершении операции через интерфейс.

Расширения (или альтернативные потоки)

*a. Каждый раз при попытке менеджера отменить создание мероприятия выполняются следующие действия.

```
  1.  FTS отображает запрос на подтверждение отмены.
  2.  Менеджер подтверждает отмену операции.
  3.  FTS удаляет несохраненные изменения.
  4.  FTS возвращается к начальному экрану управления мероприятиями.
```

*б. При каждом выходе FTS из строя.

```
Для восстановления корректной работы необходимо восстановить данные последней операции создания или редактирования мероприятия.

  1.  Менеджер повторно входит в FTS.
  2.  FTS предлагает восстановить незавершенную операцию через интерфейс.
  3.  Менеджер подтверждает восстановление.
  4.  FTS восстанавливает сохраненное состояние мероприятия.
```

2а. В EventRepository нет ни одной карты стадиона.

```
  1.  FTS сообщает менеджеру, что готовых карт стадиона нет.
  2.  Менеджер открывает панель управления картами стадиона.
  3.  FTS создаёт новую карту и сохраняет её.
  4.  Менеджер возвращается к созданию матча и выбирает созданную карту.
```

2б. Ошибка загрузки карты стадиона из хранилища.

```
  1.  FTS сообщает менеджеру о невозможности загрузить данные.
  2.  Менеджер повторяет попытку загрузки.
    2а.  Повторная загрузка завершилась неудачей.
      1. FTS отменяет операцию создания матча.
      2. Менеджер обращается в службу поддержки.
```

3а. Менеджер выбирает опцию редактирования мероприятия.

```
  1.  FTS загружает данные мероприятия и связанных матчей.
  2.  FTS получает карту стадиона из выбранного матча.
  3.  Интерфейс формирует графическую карту мест стадиона и отображает ее менеджеру.
  4.  Менеджер изменяет параметры необходимых мест.
  5.  FTS сохраняет внесенные изменения в экземпляре матча.
  6.  Менеджер завершает настройку и отправляет команду сохранения.
  7.  FTS сохраняет изменения.
  8.  FTS отправляет подтверждение об успешном обновлении мероприятия.
  9.  Менеджер получает уведомление об успешном завершении операции.
```

7а. FTS обнаруживает повреждение данных.

```
  1. FTS уведомляет менеджера об ошибке.
  2. FTS регистрирует информацию об ошибке в лог файле.
  3. FTS возвращается в начальное состояние.
  4. Менеджер начинает создание мероприятия заново.
```

8а. Менеджер хочет продолжить редактирование после сохранения.

```
  1. FTS открывает карточку сохраненного мероприятия.
  2. Менеджер продолжает редактирование.
```

9а. Ошибка сохранения в хранилище.

```
1. FTS уведомляет менеджера об ошибке сохранения.
2. FTS предлагает повторить операцию.
  2а. Повторное сохранение завершилось успешно.
    1. FTS сохраняет данные в хранилище.
    2. FTS отправляет подтверждение о завершении операции.
  2б. Повторное сохранение завершилось неудачей.
    1. FTS сохраняет информацию об ошибке в лог файле.
    2. Менеджер обращается к администратору.
```

Специальные требования.

- Сенсорный экран или клавиатура с мышью для взаимодействия с интерфейсом.
- FTS должен поддерживать визуальное отображение схемы стадиона.
- Все изменения доступности мест должны отображаться в реальном времени.
- FTS должна сохранять данные мероприятия не более чем за 5 секунд в 95% случаев.
- Необходимо обеспечить восстановление незавершенных операций после сбоя.
- FTS должен поддерживать локализацию на различные языки.
- Каждая вызванная FTS функция выводится в отдельной панели логов.
- FTS должна позволять изменять правила доступности мест без остановки работы.
