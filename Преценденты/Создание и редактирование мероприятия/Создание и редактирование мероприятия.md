Рамки. Приложение организации мероприятий и продажи билетов Stadium Management and Tickets System.

Уровень. Задача, определенная пользователем.

Основной исполнитель. Менеджер.

Заинтересованные лица и их требования. 

- Менеджер. Хочет быстро создавать и настраивать мероприятия, изменять доступность мест и сохранять изменения без ошибок.
- Посетитель. Хочет получать актуальную информацию о доступных местах и приобретать билеты только на свободные места.
- Организатор мероприятия. Хочет получать актуальную схему размещения зрителей и информацию о занятых и свободных местах.
- Компания владелец стадиона. Заинтересована в сохранности данных, устойчивости системы к сбоям и своевременном обновлении информации о мероприятиях.


Предусловия. Менеджер идентифицирован и аутентифицирован в системе. Схема стадиона доступна в базе данных.

Результаты (Постусловия).

- Новое мероприятие создано или существующее мероприятие обновлено.
- Изменения доступности мест сохранены.
- Данные мероприятия записаны в базу данных.
- Пользователь получил подтверждение успешного сохранения.

Основной успешный сценарий (или основной процесс)

1.  Менеджер инициирует управление мероприятиями, запуская контроллер.
2.  Контроллер загружает данные мероприятий из базы данных.
3.  Менеджер выбирает опцию создания нового мероприятия, создавая новый объект класса мероприятия.
4.  Контроллер загружает страндартную схему стадиона в отдельный класс и привязывает его к мероприятию.
5.  Класс интерфейса формирует графическую карту мест стадиона и отображает ее менеджеру.
6.  Менеджер изменяет параметры необходимых мест с помощью интерфейса.
7.  Котроллер сохраняет внесенные изменения в класс карты.
8.  Менеджер завершает настройку и отправляет команду сохранения.
9.  Контраллер сохраняет мероприятие и схему мест в базе данных.
10. Контраллер отправляет подтверждение успешного создания мероприятия.
11. Менеджер получает уведомление об успешном завершении операции через интерфейс.

Расширения (или альтернативные потоки)

*a. Каждый раз при попытке менеджера отменить создание мероприятия выполняются следующие действия.
```
  1.  Интерфейс отображает запрос на подтверждение отмены.
  2.  Менеджер подтверждает отмену операции.
  3.  Контроллер удаляет несохраненные изменения.
  4.  Интерфейс возвращается к начальному экрану управления мероприятиями.
```

*б. При каждом выходе системы из строя.
```
Для восстановления корректной работы необходимо восстановить данные последней операции создания или редактирования мероприятия.

  1.  Менеджер повторно входит в систему.
  2.  Контроллер предлагает восстановить незавершенную операцию через интерфейс.
  3.  Менеджер подтверждает восстановление.
  4.  Контроллер восстанавливает сохраненное состояние мероприятия.
```

2а. Ошибка загрузки схемы стадиона из базы данных.
```
  1.  Контроллер сообщает менеджеру о невозможности загрузить данные.
  2.  Менеджер повторяет попытку загрузки.
    2а.  Повторная загрузка завершилась неудачей.
      1. Контроллер отменяет операцию создания мероприятия.
      2. Менеджер обращается в службу поддержки.
```

3а. Менеджер выбирает оцпию редактирования мероприятия.  
```
  1.  Контроллер загружает схему стадиона данного мероприятия из базы данных в класс карты.
  2.  Интрефейс формирует графическую карту мест стадиона и отображает ее менеджеру.
  3.  Менеджер изменяет параметры необходимых мест.
  4.  Контроллер сохраняет внесенные изменения в классе карта стадиона.
  5.  Менеджер завершает настройку и отправляет команду сохранения.
  6.  Контроллер сохраняет изменения в базе данных.
  7.  Контроллер отправляет подтверждение об успешном обновлении мероприятия.
  8.  Менеджер получает уведомление об успешном завершении операции.
```

7а. Система обнаруживает повреждение данных.
```
  1. Контроллер уведомляет менеджера об ошибке.
  2. Контроллер регистрирует информацию об ошибке в лог файле.
  3. Контроллер возвращается в начальное состояние.
  4. Менеджер начинает создание мероприятия заново.
```

8а. Менеджер хочет продолжить редактирование после сохранения.
```
  1. Контроллер открывает карточку сохраненного мероприятия.
  2. Менеджер продолжает редактирование.
```

9а. Ошибка сохранения в базе данных.
```
1. Контроллер уведомляет менеджера об ошибке сохранения.
2. Контроллер предлагает повторить операцию.
  2а. Повторное сохранение завершилось успешно.
    1. Контроллер сохраняет данные в базе данных.
    2. Контроллер отправляет подтверждение о завершении операции.
  2б. Повторное сохранение завершилось неудачей.
    1. Контроллер сохраняет информацию об ошибке в лог файле.
    2. Менеджер обращается к системному администратору.
```

Специальные требования.
- Сенсорный экран или клавиатура с мышью для взаимодействия с интерфейсом.
- Интерфейс должен поддерживать визуальное отображение схемы стадиона.
- Все изменения доступности мест должны отображаться в реальном времени.
- Система должна сохранять данные мероприятия не более чем за 5 секунд в 95% случаев.
- Необходимо обеспечить восстановление незавершенных операций после сбоя.
- Интерфейс должен поддерживать локализацию на различные языки.
- Система должна позволять изменять правила доступности мест без остановки работы.
