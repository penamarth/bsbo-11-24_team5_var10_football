### Рамки
Football Ticket System

### Уровень
Задача, определённая пользователем.

### Основной исполнитель
Зритель (владелец билета или абонемента).

### Заинтересованные лица и их требования
- **Зритель:** хочет быстро, без очереди и без участия персонала пройти на стадион по своему билету/абонементу и узнать, где находится его место.
- **Стадион:** хочет пропускать на трибуны только зрителей с действительными билетами/абонементами и обеспечить быструю пропускную способность входной зоны.
- **Служба охраны:** хочет, чтобы по одному билету нельзя было пройти дважды, чтобы попытки прохода по поддельным, возвращённым или чужим билетам сразу становились ей известны, и чтобы у неё были данные о занятых местах.
- **Контролёр на входе:** хочет снизить нагрузку, переложив проверку билетов на турникеты, и вмешиваться только в спорных случаях.
- **Организаторы футбольных матчей:** хотят, чтобы вход на матч проходил без задержек и инцидентов, так как это влияет на рейтинг матча.
- **Система анализа прибыльности мероприятия:** заинтересована в получении данных о фактической посещаемости матча.

### Предусловия
- Турникет с QR-сканером исправен и находится в режиме ожидания.
- На стадионе идёт вход на текущий матч (открыто время прохода).
- У зрителя есть купленный билет/абонемент с QR-кодом (бумажный или на экране телефона).
- Локальная БД доступна, при её недоступности вызывается сотрудник охраны.
- Для синхронизации доступен удалённый сервер, при недоступности запрос ставится в очередь.

### Результаты (Постусловия)
- Зритель с действительным билетом/абонементом прошёл через турникет на территорию стадиона.
- Билет помечен использованным (для абонемента — использованным на текущий матч), повторный проход по нему невозможен.
- Место зрителя отмечено занятым, данные переданы службе охраны.
- FTS фиксирует проход локально, после чего пытается синхронизироваться с удалённым хранилищем.
- Результат операции (успешный проход или отказ с причиной) фиксируется в журнале аудита.

### Основной успешный сценарий
1. FTS отображает на экране турникета приглашение отсканировать QR-код.
2. Зритель подносит QR-код билета/абонемента к сканеру.
3. FTS считывает QR-код и запрашивает у хранилища билетов информацию о билете/абонементе.
4. Локальная БД проверяет:
   - подлинность билета/абонемента
   - что билет/абонемент не был возвращён
   - что билет относится к текущему матчу (абонемент действует на текущий матч)
   - что по билету/абонементу ещё не было прохода на текущий матч
5. Если проход разрешён, FTS показывает зрителю сектор, ряд и место.
6. FTS разблокирует турникет.
7. Зритель проходит через турникет.
8. Турникет фиксирует проход, FTS блокирует турникет.
9. FTS регистрирует проход в локальной БД.
10. Хранилище билетов помечает билет/абонемент использованным на текущий матч.
11. FTS передаёт службе охраны запись о занятом месте.
12. FTS отправляет данные о проходе на удалённый сервер для синхронизации.
13. Результат операции фиксируется в журнале аудита.
14. Турникет возвращается в режим ожидания.

### Расширения (альтернативные потоки)

*а. При неисправимой ошибке
```
1. Система выводит сообщение, просящее зрителя обратиться к контролёру на входе
2. Турникет остаётся заблокированным
3. Система закрывает сообщение через некоторое время или при нажатии пользователя
```

3а. QR-код не удалось считать
```
1. FTS сообщает об ошибке чтения и предлагает повторить сканирование
2. Зритель сканирует QR-код повторно
3. Если после трёх попыток код не считан, FTS предлагает обратиться к контролёру на входе
4. Турникет возвращается в режим ожидания
```

4а. Билет/абонемент не найден (поддельный)
```
1. FTS выводит сообщение "Билет недействителен, обратитесь к контролёру"
2. FTS уведомляет службу охраны о попытке прохода по недействительному билету
3. Турникет остаётся заблокированным
4. Результат фиксируется в журнале аудита
5. Турникет возвращается в режим ожидания
```

4б. По билету/абонементу уже был проход на текущий матч
```
1. FTS выводит сообщение "Билет уже использован" с указанием времени и турникета прохода
2. FTS уведомляет службу охраны о попытке повторного прохода
3. Турникет остаётся заблокированным
4. Результат фиксируется в журнале аудита
5. Турникет возвращается в режим ожидания
```

4в. Билет/абонемент был возвращён
```
1. FTS выводит сообщение "Билет был возвращён и недействителен"
2. Турникет остаётся заблокированным
3. Результат фиксируется в журнале аудита
4. Турникет возвращается в режим ожидания
```

4г. Билет на другой матч (абонемент не действует на текущий матч)
```
1. FTS выводит сообщение с датой и названием матча, на который действует билет
2. Турникет остаётся заблокированным
3. Турникет возвращается в режим ожидания
```

4д. Локальная БД недоступна
```
1. FTS выводит сообщение "Проход временно невозможен, обратитесь к контролёру"
2. FTS вызывает сотрудника охраны
3. Турникет переводится в режим ручного управления контролёром
```

7а. Зритель не прошёл через турникет в течение 10 секунд
```
1. FTS блокирует турникет
2. Проход не регистрируется, билет остаётся действительным
3. Турникет возвращается в режим ожидания
```

12а. Не удалось связаться с удалённым сервером
```
1. FTS ставит запрос на синхронизацию в локальную очередь
2. Запрос отправляется повторно при восстановлении связи
3. Турникет возвращается в режим ожидания
```

### Специальные требования
- Проверка билета и разблокировка турникета должны занимать не более 2 секунд.
- Сканер должен считывать QR-код как с бумаги, так и с экрана телефона.
- Сообщения на экране турникета должны дублироваться пиктограммами и быть доступны на нескольких языках для туристов.
- Система должна работать без подключения к интернету: проверка выполняется по локальной БД, общей для всех турникетов стадиона.
- Одновременная работа нескольких турникетов не должна позволять пройти по одному билету дважды.
- Должна поддерживаться синхронизация с удалённым сервером.
- Все проходы и отказы должны фиксироваться в журнале аудита.

### Список технологий и типов данных
- QR-сканер турникета.
- Контроллер турникета (управление замком и датчик прохода).
- Реляционная БД для хранения информации о билетах/абонементах и проходах.
- REST API для обращения к удалённому серверу.
- Локальная очередь для отложенной отправки запросов.
- Интеграция с системой службы охраны для передачи данных о занятых местах и тревожных событиях.
- Журнал аудита для фиксации результатов прохода.

### Открытые вопросы
- Разрешён ли повторный вход на стадион по тому же билету после выхода (например, в перерыве)?
- Нужно ли проверять личность владельца абонемента (фото, документ), чтобы абонементом не пользовались другие люди?
- Как организовать проход детей, которым не требуется отдельный билет?
