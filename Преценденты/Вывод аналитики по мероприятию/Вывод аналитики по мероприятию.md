### Рамки
Football Ticket System (FTS)

### Уровень
Задача, определённая пользователем.

### Основной исполнитель
Менеджер.

### Заинтересованные лица и их требования
- **Менеджер:** хочет быстро получать наглядную аналитику по мероприятию: выручку, количество проданных билетов и абонементов, заполняемость стадиона, чтобы оценивать результаты и планировать будущие мероприятия.
- **Организатор мероприятия:** хочет видеть итоги прошедшего мероприятия и понимать, насколько прибыльным оно оказалось.
- **Компания владелец стадиона:** заинтересована в достоверных данных о выручке и загрузке стадиона для принятия решений.

### Предусловия
- Менеджер идентифицирован и аутентифицирован в FTS.
- В Event Storage хранятся сведения о мероприятии, в Pass Storage — о проданных на него билетах и абонементах.

### Результаты (Постусловия)
- Показатели мероприятия рассчитаны.
- Отчет по мероприятию сформирован и отображен менеджеру.
- Отчет сохранен в Pass Storage и доступен для выгрузки.

### Основной успешный сценарий
1. Менеджер инициирует просмотр аналитики по мероприятиям, запуская FTS.
2. FTS загружает из Event Storage список мероприятий, по которым есть данные о продажах.
3. FTS отображает список мероприятий менеджеру.
4. Менеджер выбирает мероприятие, и FTS находит соответствующий объект класса мероприятия.
5. FTS загружает из Pass Storage сведения о проданных билетах и абонементах.
6. FTS запрашивает у класса карты стадиона статистику занятых мест.
7. FTS создает экземпляр класса отчета, передавая ему данные о мероприятии, продажах и занятых местах, после чего класс отчета рассчитывает показатели мероприятия: выручку, количество продаж, заполняемость стадиона и распределение мест по статусам. FTS отображает отчет менеджеру.
8. Менеджер сохраняет (выгружает) отчет.
9. FTS сохраняет экземпляр класса отчета в Pass Storage и отправляет менеджеру подтверждение успешного формирования аналитики.

### Расширения (альтернативные потоки)

*a. Каждый раз при попытке менеджера закрыть просмотр аналитики
```
1. FTS возвращается к списку мероприятий.
2. FTS сбрасывает несохраненный отчет.
```

*б. При каждом выходе FTS из строя
```
Для восстановления корректной работы необходимо повторно сформировать отчет.

1. Менеджер повторно входит в FTS.
2. FTS предлагает повторить формирование аналитики.
3. Менеджер подтверждает повторное формирование.
4. Класс отчета заново рассчитывает показатели мероприятия.
```

2а. В Event Storage нет мероприятий с данными о продажах
```
1. FTS сообщает менеджеру об отсутствии данных о продажах.
2. FTS предлагает выбрать другое мероприятие или вернуться позже.
3. Менеджер завершает просмотр аналитики.
```

5а. Ошибка загрузки данных о продажах из Pass Storage
```
1. FTS сообщает менеджеру о невозможности загрузить данные.
2. Менеджер повторяет попытку загрузки.
    2а. Повторная загрузка завершилась неудачей.
        1. FTS отменяет формирование отчета.
        2. Менеджер обращается к администратору системы.
```

6а. Обнаружены неполные данные о продажах
```
1. FTS уведомляет менеджера о некорректности данных.
2. FTS регистрирует информацию об ошибке.
3. FTS помечает отчет как предварительный.
4. Менеджер принимает отчет и сообщает об ошибке администратору.
```

9а. Ошибка сохранения отчета в Pass Storage
```
1. FTS уведомляет менеджера об ошибке сохранения.
2. FTS предлагает повторить операцию.
    2а. Повторное сохранение завершилось успешно.
        1. FTS сохраняет отчет.
        2. FTS подтверждает завершение операции.
    2б. Повторное сохранение завершилось неудачей.
        1. FTS сохраняет информацию об ошибке.
        2. Менеджер обращается к администратору системы.
```

### Специальные требования
- Интерфейс должен поддерживать визуальное отображение аналитики в виде таблиц и диаграмм.
- FTS должна формировать отчет не более чем за 5 секунд в 95% случаев.
- Данные о продажах должны быть актуальны на момент формирования отчета.
- Необходимо обеспечить сохранение сформированного отчета после сбоя.
- Интерфейс должен поддерживать локализацию на различные языки.
- Доступ к аналитике должен быть разграничен по ролям пользователей.
- Должна быть возможность выгрузки отчета в файл.

### Список технологий и типов данных
- Данные о мероприятиях хранятся в Event Storage.
- Данные о проданных билетах и абонементах загружаются из Pass Storage.
- Идентификатор мероприятия выбирается из списка.
- Показатели мероприятия рассчитываются на основе данных о продажах и схемы стадиона.
- Отчет сохраняется в Pass Storage, а факт выгрузки фиксируется в журнале аудита.

### Частота использования
После каждого мероприятия, несколько раз в месяц.
