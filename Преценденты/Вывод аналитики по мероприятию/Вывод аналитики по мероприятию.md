### Рамки
Приложение организации мероприятий и продажи билетов Stadium Management and Tickets System

### Уровень
Задача, определённая пользователем.

### Основной исполнитель
Менеджер.

### Заинтересованные лица и их требования
- **Менеджер:** хочет быстро получать наглядную аналитику по мероприятию: выручку, количество проданных билетов и абонементов, заполняемость стадиона, чтобы оценивать результаты и планировать будущие мероприятия.
- **Организатор мероприятия:** хочет видеть итоги прошедшего мероприятия и понимать, насколько прибыльным оно оказалось.
- **Компания владелец стадиона:** заинтересована в достоверных данных о выручке и загрузке стадиона для принятия решений.

### Предусловия
- Менеджер идентифицирован и аутентифицирован в системе.
- В базе данных хранятся сведения о мероприятии и проданных на него билетах и абонементах.

### Результаты (Постусловия)
- Показатели мероприятия рассчитаны.
- Отчет по мероприятию сформирован и отображен менеджеру.
- Отчет сохранен в базе данных и доступен для выгрузки.

### Основной успешный сценарий
1. Менеджер инициирует просмотр аналитики по мероприятиям, запуская контроллер аналитики.
2. Контроллер загружает из базы данных список мероприятий, по которым есть данные о продажах.
3. Класс интерфейса аналитики отображает список мероприятий менеджеру.
4. Менеджер выбирает мероприятие, и контроллер находит соответствующий объект класса мероприятия.
5. Контроллер загружает из базы данных сведения о проданных билетах и абонементах.
6. Контроллер запрашивает у класса карты стадиона статистику занятых мест и рассчитывает показатели мероприятия: выручку, количество продаж, заполняемость стадиона и распределение мест по статусам.
7. Контроллер заносит рассчитанные показатели в экземпляр класса отчета, и класс интерфейса аналитики отображает отчет менеджеру.
8. Менеджер сохраняет (выгружает) отчет.
9. Контроллер сохраняет экземпляр класса отчета в базе данных и отправляет подтверждение успешного формирования аналитики через класс интерфейса.

### Расширения (альтернативные потоки)

*a. Каждый раз при попытке менеджера закрыть просмотр аналитики
```
1. Класс интерфейса аналитики возвращается к списку мероприятий.
2. Класс интерфейса аналитики сбрасывает несохраненный отчет.
```

*б. При каждом выходе системы из строя
```
Для восстановления корректной работы необходимо повторно сформировать отчет.

1. Менеджер повторно входит в систему.
2. Класс интерфейса аналитики предлагает повторить формирование аналитики.
3. Менеджер подтверждает повторное формирование.
4. Контроллер заново рассчитывает показатели мероприятия.
```

2а. В базе данных нет мероприятий с данными о продажах
```
1. Класс интерфейса аналитики сообщает менеджеру об отсутствии данных о продажах.
2. Класс интерфейса аналитики предлагает выбрать другое мероприятие или вернуться позже.
3. Менеджер завершает просмотр аналитики.
```

5а. Ошибка загрузки данных о продажах из базы данных
```
1. Класс интерфейса аналитики сообщает менеджеру о невозможности загрузить данные.
2. Менеджер повторяет попытку загрузки.
    2а. Повторная загрузка завершилась неудачей.
        1. Контроллер отменяет формирование отчета.
        2. Менеджер обращается к администратору системы.
```

6а. Обнаружены неполные данные о продажах
```
1. Класс интерфейса аналитики уведомляет менеджера о некорректности данных.
2. Контроллер регистрирует информацию об ошибке.
3. Контроллер помечает отчет как предварительный.
4. Менеджер принимает отчет и сообщает об ошибке администратору.
```

9а. Ошибка сохранения отчета в базе данных
```
1. Класс интерфейса аналитики уведомляет менеджера об ошибке сохранения.
2. Класс интерфейса аналитики предлагает повторить операцию.
    2а. Повторное сохранение завершилось успешно.
        1. Контроллер сохраняет отчет.
        2. Контроллер подтверждает завершение операции.
    2б. Повторное сохранение завершилось неудачей.
        1. Контроллер сохраняет информацию об ошибке.
        2. Менеджер обращается к администратору системы.
```

### Специальные требования
- Интерфейс должен поддерживать визуальное отображение аналитики в виде таблиц и диаграмм.
- Система должна формировать отчет не более чем за 5 секунд в 95% случаев.
- Данные о продажах должны быть актуальны на момент формирования отчета.
- Необходимо обеспечить сохранение сформированного отчета после сбоя.
- Интерфейс должен поддерживать локализацию на различные языки.
- Доступ к аналитике должен быть разграничен по ролям пользователей.
- Должна быть возможность выгрузки отчета в файл.

### Список технологий и типов данных
- Данные о мероприятиях хранятся в базе данных.
- Данные о проданных билетах и абонементах загружаются из базы данных.
- Идентификатор мероприятия выбирается из списка.
- Показатели мероприятия рассчитываются на основе данных о продажах и схемы стадиона.
- Отчет сохраняется в базе данных, а факт выгрузки фиксируется в журнале аудита.

### Частота использования
После каждого мероприятия, несколько раз в месяц.
