### Рамки
Football Ticket System

### Уровень
Задача, определённая пользователем.

### Основной исполнитель
Покупатель.

### Заинтересованные лица и их требования
- **Покупатель:** хочет быстро купить билет на матч или абонемент на сезон, выбрать удобное свободное место и сразу получить билет/абонемент и чек, а также электронную копию билета/абонемента на электронную почту.
- **Стадион:** хочет продавать как можно больше билетов и абонементов без ошибок и без повторной продажи одного и того же места.
- **Организаторы футбольных матчей:** хотят высокой заполняемости стадиона, чтобы повышался рейтинг матчей.
- **Кассир:** хочет снизить нагрузку, переложив большую часть продаж на КСО.
- **Служба охраны:** хочет, чтобы каждый проданный билет/абонемент имел уникальный QR/штрихкод для проверки на входе.
- **Бухгалтерская система:** заинтересована в корректном учёте поступивших оплат.
- **Система анализа прибыльности мероприятия:** заинтересована в корректном учёте продаж при расчёте выручки.
- **Система почтовых уведомлений:** заинтересована в получении корректного адреса электронной почты покупателя и данных билета/абонемента для отправки письма.

### Предусловия
- КСО исправна и доступна покупателю.
- Продажа билетов на матч или абонементов на сезон открыта.
- Принтер КСО исправен, есть бумага для печати билетов и чеков.
- Локальная БД доступна, при её недоступности вызывается сотрудник поддержки.
- Для оплаты картой доступен банковский API, при недоступности удалённого сервера предлагается оплатить наличными.
- Для синхронизации доступен удалённый сервер, при недоступности запрос ставится в очередь.
- Для отправки писем доступна система почтовых уведомлений, при её недоступности письмо ставится в очередь.

### Результаты (Постусловия)
- Покупатель получает билет на выбранный матч или абонемент на сезон с уникальным QR/штрихкодом.
- Выбранное место помечается как занятое (для абонемента — на все матчи сезона) и больше не может быть продано ни через одну кассу.
- FTS оформляет продажу локально, после чего пытается синхронизироваться с удалённым хранилищем.
- Покупателю выдаётся чек.
- На электронную почту покупателя отправляется письмо с электронной копией билета/абонемента.
- Результат операции фиксируется в журнале аудита.

### Основной успешный сценарий
1. Покупатель выбирает в меню "Покупка билета/абонемента".
2. FTS запрашивает у хранилища билетов список ближайших матчей и абонементов, доступных для продажи.
3. FTS показывает покупателю список матчей и абонементов.
4. Покупатель выбирает матч (для покупки билета) или сезон (для покупки абонемента).
5. FTS запрашивает у хранилища билетов схему стадиона со свободными местами на выбранный матч/сезон.
6. FTS показывает покупателю схему стадиона со свободными местами.
7. Покупатель выбирает место.
8. Хранилище билетов проверяет, что место всё ещё свободно, и бронирует его на время оплаты.
9. FTS показывает покупателю матч/абонемент, место и стоимость.
10. Покупатель подтверждает покупку и выбирает способ оплаты (наличные или карта).
11. FTS предлагает ввести адрес электронной почты для получения электронной копии билета/абонемента.
12. Покупатель вводит адрес электронной почты.
13. FTS предлагает внести оплату.
14. Покупатель вносит наличные или прикладывает карту.
15. Если оплата наличными, FTS принимает наличные и выдаёт сдачу.
16. Если оплата картой, FTS отправляет запрос на удалённый сервер для списания средств с карты.
17. Удалённый сервер отправляет запрос на списание средств через банковский API.
18. FTS создаёт билет/абонемент в хранилище билетов.
19. Хранилище билетов помечает место как занятое и снимает бронь.
20. FTS печатает билет/абонемент с QR/штрихкодом и выдаёт покупателю чек.
21. FTS отправляет через систему почтовых уведомлений письмо с электронной копией билета/абонемента на электронную почту покупателя.
22. Результат операции фиксируется в журнале аудита.
23. Интерфейс возвращается к начальному экрану.

### Расширения (альтернативные потоки)

*a. При попытке покупателя отменить покупку
```
1. КСО отображает запрос на подтверждение отмены
2. Покупатель подтверждает отмену операции
3. Если место уже забронировано, хранилище билетов снимает бронь
4. КСО возвращается к начальному экрану
```

*б. При неисправимой ошибке
```
1. Система выводит сообщение, просящее пользователя обратиться к ассистенту за помощью
2. Если место уже забронировано, хранилище билетов снимает бронь
3. Система закрывает сообщение через некоторое время или при нажатии пользователя
```

8а. Выбранное место уже занято (продано через другую кассу)
```
1. КСО сообщает покупателю, что место уже занято
2. КСО закрывает сообщение через некоторое время или при нажатии пользователя
3. КСО возвращается к начальному экрану, покупатель может начать покупку заново
```

12а. Покупатель ввёл некорректный адрес электронной почты
```
1. КСО сообщает покупателю, что адрес электронной почты введён неверно
2. КСО предлагает ввести адрес ещё раз
3. Продолжение с шага 12
```

14а. Покупатель не внёс оплату за отведённое время
```
1. Хранилище билетов снимает бронь с места
2. КСО сообщает покупателю, что время на оплату истекло
3. КСО возвращается к начальному экрану
```

16а. Не удалось связаться с удалённым сервером
```
1. КСО предлагает оплатить наличными
2а. Покупатель согласился
    1. КСО принимает наличные и выдаёт сдачу
    2. Продолжение с шага 18
2б. Покупатель отказался
    1. Хранилище билетов снимает бронь с места
    2. КСО возвращается к начальному экрану
```

17а. Не удалось списать средства с карты (банк отклонил оплату или банковский API недоступен)
```
1. КСО предлагает оплатить наличными или другой картой
2а. Покупатель выбрал наличные
    1. КСО принимает наличные и выдаёт сдачу
    2. Продолжение с шага 18
2б. Покупатель выбрал другую карту
    1. КСО пытается списать средства с другой карты
    2. Если списать средства не удалось, возвращаемся к пункту 1
2в. Покупатель отказался от покупки
    1. Хранилище билетов снимает бронь с места
    2. КСО возвращается к начальному экрану
```

21а. Не удалось отправить письмо (система почтовых уведомлений недоступна)
```
1. FTS ставит письмо в очередь на отложенную отправку
2. FTS повторяет отправку письма с заданным интервалом, пока письмо не будет отправлено
3. Продолжение с шага 22
```

### Специальные требования
- Интерфейс должен быть доступен на нескольких языках для туристов.
- Система должна быть устойчива к сбоям, обеспечивая непрерывность работы при проблемах с сервером или сетью.
- Одно и то же место не может быть продано дважды при одновременной работе нескольких касс и КСО.
- Бронь места должна сниматься автоматически, если оплата не поступила за отведённое время.
- После каждой успешной покупки на электронную почту покупателя должно отправляться письмо с электронной копией билета/абонемента.
- Должна поддерживаться синхронизация с удалённым сервером.
- Все операции продажи должны фиксироваться в журнале аудита.

### Список технологий и типов данных
- REST API для обращения к удалённому серверу.
- Реляционная БД для хранения информации о матчах, местах, билетах/абонементах и бронях.
- API банка для списания средств с карты.
- API системы почтовых уведомлений (SMTP) для отправки писем с электронной копией билета/абонемента.
- Сенсорный экран для выбора матча и места на схеме стадиона и ввода адреса электронной почты.
- Купюроприёмник и платёжный терминал для приёма оплаты.
- Принтер для печати билетов/абонементов с QR/штрихкодом и чеков.
- Локальная очередь для отложенной отправки запросов и писем.
- Журнал аудита для фиксации результатов продажи.
